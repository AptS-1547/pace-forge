
这一版主要修一个「用户看着屏幕就发现不对」的规划 bug，另外把账号库和口令这几处早年图省事的地方补上。

## 选了「自动规划」却在操场绕圈：用户的选择被静默改写

控制台结果面板写着「模式：已连服务端 · 自由路线」，紧挨着「实际路线：操场绕圈」，地图上那条蓝线画在一片绿地和餐厅旁边——那地方根本没有跑道。

根因在 `dry_run`：判断要不要按打卡点反推操场，只看了 `run_mode == 1`（记分跑）一条，控制台选的路线压根没进决策。`try_stadium_track` 是纯几何判据——打卡点外框长轴 55~240m、短轴 25~160m 加上 PCA 朝向，够了就按比例拟合出一个椭圆。教学楼四角、宿舍区、围成一片的打卡点很容易凑出这个尺寸，于是「自动规划」被翻成操场，在质心处画出一条哪儿都不挨着的椭圆。

修法是让选择真正生效：`RunParams` 新增 `prefer_stadium`，由请求里的 `mode` 决定，只有明确选「操场绕圈」才反推跑道，其余一律走路线规划（拉 OSM 路网、串打卡点）。CLI 没有这个选项，默认 `true`，行为与前几版一致。

顺带说明：选「操场绕圈」但打卡点不像操场时，仍然会退回路线规划并在界面标红提示——这条原有逻辑没动。

## 账号密文换成随机盐 + IV（#15）

早先的账号库，同一个密码配同一把固定盐，密文在磁盘上长得一样；IV 也是固定的。现在每条记录独立随机盐 + IV，账号库落一个密钥指纹，密钥换了能立刻看出来（而不是等到解密失败才发现读错了库）。已有账号库首次读取时按老格式解、按新格式重写，不需要手动迁移。

## 控制台两处加固

- 口令比较改成常量时间：原来逐字节短路比较，响应时间差能把口令一个字节一个字节摸出来。这是本地控制台，但从公网开着 0.0.0.0 的人不少，值得改。
- 请求并发加上限：超出直接回 503，不再无上限堆线程——扫码枪式连点或者被扫端口时，进程不会先被自己拖死。
