修 bug 为主的一个版本，没有新功能。

## 修了什么

### 短距离轨迹会直接崩掉

平均点距小于 2.79 米的轨迹（100 米 40 个点这种）在起步段压缩时会 panic，整条生成链路出不了报文。原因是把新预算夹到 `[下限, 总长×5%]` 时，下限可能已经顶到上限之上，而 Rust 的 `f64::clamp` 在 min > max 时是崩，不是截断。绕操场跑两圈（点距 15 米左右）碰不到，一直是测试盲区。

### "现在跑"生成的记录整条落在未来

选「现在开跑」时，开始时间取的是「服务器现在 + 0~5 秒」，而结束时间是「开始 + 时长」。于是整条记录的时间窗必然在服务器未来，按服务端的「开始 + 时长 ≤ 现在」判据应当被驳回，失败还会计入风控。本地自检对这一项完全失明——它拿本机时钟自己跟自己比。现在改成往回退一整段时长再留几秒余量，并给自检加了一条「结束时间不得在服务器未来」的检查。

同一个判据还有另一个入口：补跑时前端算好的时刻带本机时钟误差，而校时拿到的偏差只写进了日志。本机快十分钟时，补跑记录照样会落到未来轴。这条也一起修了。

### 路网规划漏掉打卡点却说成功

沿真实道路生成轨迹时，文档承诺「经过所有必过点」，但实现里只在走过附近时标记完成，循环结束从不检查有没有遗漏。漏掉的点会在下游被当成弦硬钉进路径，弦线中间可能穿楼穿水，而相邻点跳变检查只看间距，查不出「绕过了打卡点」这件事。现在有漏点就明确报错，退回几何规划。

### 口令模式下整个控制台打不通

设了 `PACE_FORGE_TOKEN` 之后，前端一个请求都不带 `X-Pace-Token`。页面本身放行，但 `/api/*` 一律 401——除了首页全废。现在从 URL 的 `?token=` 取到口令存进 sessionStorage，所有请求统一带上，用完立刻从地址栏抹掉（否则会进浏览器历史、Referer 和随手复制的链接里）。

退出登录那个裸 `fetch` 也补上了口令，服务端会话和本地登录态才能一起清干净。

### 坏请求只回空体 500

请求体不是 JSON、或者 `/api/record/abc` 这种 id 写错的时候，服务端只往 stderr 记一行，从不回响应，最后由 HTTP 库兜底发一个空体 500。调用方分不清「请求写错了」和「服务器崩了」。九个入口全部改成 400 + JSON 正文。

### 提交被驳回时看不到针对性提示

签名错误、不在跑步时段、账号在其他设备登录、请求过于频繁——这四条针对性提示写好了，但永远走不到。因为上游的响应检查在错误码非成功时直接返回错误，后面那段 `if err != 0 && err != 10000` 恒为假。用户实际只看到「业务错误 error=Some(11016)」这种通用文案，而四条提示覆盖的恰好是最高频的驳回原因。

### 步频检查用的是比服务端更窄的尺子

策略里没下发步频区间时，本地自检回退到 100~230，而服务端实发口径是 60~250。合法步频 60~99 会被本地拦死——等于自己把好单挡在门外。

### 登出把认不出的响应当成功

响应解析失败时退化成空对象，再配合「没有错误码就当成功」，一段 HTML 错误页、空响应、被网关截断的内容都会被判成「登出成功」，而服务端会话其实还活着。现在解析失败明确回「没确认成功」。

### 状态锁中毒后只能重启

持锁的线程只要 panic 一次，锁就永久中毒，之后每个请求都跟着失败。现在强制取回内层值并留一行日志——对本机单进程控制台来说，「数据可能不一致」远好过「必须重启」。

### 文件权限有个 0644 的窗口

会话文件先创建（走 umask，常见 0644）再 chmod 0600，中间那个微秒级窗口里，同机其他用户能读到 token 和加密后的密码。改成创建时就是 0600。

### 其他

- 上游瞬时空响应不再写进点位缓存（否则 5 分钟内都命中空缓存，用户只看到「这个围栏没点位」）
- 请求体加了 8 MB 上限（之前声明一个大长度却只发一个字节，就能把线程钉住）
- 前端拿到非 JSON 响应时，报错带上状态码和 content-type，不再是那句看不懂的 `Unexpected token u in JSON at position 0`
- 验签的比对修了量纲错误（原来拿原始摘要字节去比 32 字符的 hex 字符串，恒不相等。默认不开验签所以一直没暴露，一旦打开会拒绝所有合法响应）
- `ago` 的分钟上限改成和 3 天口径一致（原来多算了一天）
