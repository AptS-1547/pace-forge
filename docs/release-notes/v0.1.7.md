这一版修了两个「用户截图直接实锤」的显示问题——配速图纵轴爆表和操场轨迹超长变形，都是对着 issue 里的日志和截图一条条核出来的。顺带把隔壁同类工具全军覆没的那类 IP 风险做成了可见的自检项。

## 配速图纵轴被顶爆：我自己修出来的回归

11-15 那次为了「配速图开头断线」把起步窗口（GPS 刚锁定那 ~90 秒）的配速按几何小速度上送，0.15~0.2 m/s 折成 90~110 分/公里。App 配速图的纵轴跟着数据极值走，一两个这样的点就把整张图量程撑到 156'~160'，6 分配的曲线被压成贴地一条线——用户看到的现象是「前几分钟没有数据」。

回退成真机口径：主校准样本前 18 点配速就是全 0（GPS 没锁定就是没配速），开头一分来钟「没线」是真机同款行为，纵轴回到正常量程主体曲线才可读。两害取轻，那次的改动是我自己引入的回归，认。

## 操场绕圈一圈量出 429m：抖动不随采样间距缩放

用户日志实锤：外框按标准 400m 认出（半径 36.8 直道 84 都对），生成后实测 2145.4m / 目标 2000m，单圈 429m，地图上轨迹呈「河流状」宽带。

根因是操场 GPS 抖动参数（θ=0.15、σ=1.1）拿真机 14.9m 点距标定后写死；间距缩到 5m 时逐点噪声占比放大三倍，弦长全程被撑长。现在 θ 按点距线性缩放（相关长度按米恒定）、σ 按点距开方缩放（漂移带宽按米恒定），14.9m 间距下行为一位不动，5m 间距的长度膨胀从 7.3% 回落到 1% 上下。2km 目标现在落在 2040~2070m。

复核时挖出两个潜伏问题一起修了：

- 只有 4 个角点位、没有「田径场中」点位的学校，场心检测会把一个角点错当内场点剔除，椭圆整体画偏 33m 还漏那个角的打卡。现在只有「离质心不足第二近点一半」的才算场心。
- 打卡点吸附详情进了日志：几个点位距跑道 >16m、最远几米，一眼可辨「轨迹穿进内场」是打卡点位置（必须经过的代价）还是跑偏；生成后复核全部点位贴合度，有够不着的直接放弃操场形状回退路线规划，不让计分跑交一条必被判漏打卡的轨迹白烧额度。

## 出口 IP 自检：隔壁全军覆没的教训做成可见项

同类工具栽在「IP 提交异常」——出口 IP 归属地和学校所在地对不上，服务端成片清理记录。pace-forge 不改、不选、不伪造出口 IP；现在把**真实**出口 IP 探出来亮在顶栏（ipify → httpbin 兜底，5 秒超时，缓存 5 分钟，失败显示「出口未知」不阻塞任何功能）。部署在异地服务器的人打开页面就能看出「学校在新疆、出口在北京」这种特征。显示只是自检，消除风险得靠换网络，软件改不了物理位置。

## 必到点标记兜底不再静默

必到点的 10m 命中圈全被起点/灰点占住时，标记会放开半径落在圈外最近采样上——这个兜底之前完全静默，偏到几十米也没人知道。现在偏出命中圈就告警：点位名 + 偏离米数。只告警不挪标记，官方客户端在冲突场景的行为没有样本依据，乱挪比偏着更冒险。
